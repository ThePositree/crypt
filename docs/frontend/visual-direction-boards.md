# Visual Direction Boards

Status: awaiting owner selection.

These boards are direction studies for the first public `crypt` documentation
site. They are not production assets and do not finalize the design system.

## Shared Product Constraints

- Site name: `crypt`.
- Audience: public developers and crypto-native readers.
- Surface: production-grade documentation platform, not an MVP landing page.
- First screen: short intro, then fast entry into docs.
- Structure: separate routes with top navigation for Docs, Architecture,
  Research, and Backtester.
- Content: English-only, source-backed documentation content copied or
  transformed into the frontend content structure.
- Required affordances: full-text search, sidebar navigation, syntax
  highlighting, visual diagrams, safety callouts, public live runtime flow, and
  curated research/archive coverage.
- Visual preference: lo-fi cartoon in pastel tones, with a primary hero
  illustration.

## Board 1: Pastel Lab Docs

Core idea: a soft research-lab docs platform where strategy experiments,
backtests, and live execution feel organized, approachable, and audit-friendly.

Palette:

- warm paper background;
- pale mint for research and signals;
- muted coral for warnings and correctness callouts;
- ink gray for body text;
- soft blue for links and active navigation.

Typography:

- clean product-docs sans for UI and prose;
- compact monospace for commands, config keys, and strategy filenames;
- restrained heading scale to keep the site documentation-first.

Hero illustration:

- lo-fi desk scene with candles, charts, notebook pages, and a small terminal;
- no exchange-screen drama or high-volatility neon.

Layout:

- first screen has a concise intro beside or above a visual docs entry grid;
- docs pages use a left sidebar, content column, and optional right table of
  contents;
- safety callouts appear as soft bordered blocks with strong labels.

Best for:

- making the project feel serious but readable;
- long-form technical docs;
- production-grade documentation without losing warmth.

Risk:

- can become too gentle for crypto-native readers if diagrams and technical
  density are underplayed.

## Board 2: Lo-Fi Terminal Garden

Core idea: crypto and CLI motifs softened into a lo-fi pastel environment:
terminal panels, market ticks, and config flows placed in a calm illustrated
workspace.

Palette:

- dusty lavender background accents;
- sage green for healthy flows and reproducibility;
- peach for warnings;
- charcoal text;
- faded cyan for command links and selected states.

Typography:

- docs sans for readable prose;
- visibly prominent monospace blocks for CLI/setup pages;
- small uppercase labels for system states and runtime phases.

Hero illustration:

- cartoon terminal surrounded by soft market-candle plants, docs tabs, and
  small status indicators;
- the terminal is friendly, not hacker-themed.

Layout:

- home page intro is short, then a command/search-forward docs entry;
- architecture and live pages can use terminal-like flow blocks;
- search is visually central.

Best for:

- developer familiarity;
- setup, CLI, and runtime-flow pages;
- making the toolchain feel tangible.

Risk:

- too much terminal styling could fight the requested product-docs platform
  feel unless carefully restrained.

## Board 3: Workbench Atlas

Core idea: the site is a map of the workbench: Research, Backtester, Live,
Architecture, Setup, API, CLI, and Archive are treated as connected regions in
one system.

Palette:

- pale sky base;
- soft yellow for overview/orientation;
- muted teal for architecture and data;
- rose for risk/safety notes;
- deep graphite for text.

Typography:

- sturdy documentation sans;
- slightly more expressive headings for atlas/map sections;
- monospace used sparingly for file paths and commands.

Hero illustration:

- lo-fi illustrated map of the system: data cache, strategy archive,
  backtester, live runtime, and docs routes connected by paths.

Layout:

- first screen intro plus a large route map into documentation;
- section landing pages use diagram-led orientation before full markdown
  content;
- sidebars mirror the map structure.

Best for:

- explaining a complex repository to new readers;
- making manual IA obvious;
- showing how research, regression, and live execution relate.

Risk:

- map metaphors can become decorative if every route does not lead to concrete
  source-backed content.

## Board 4: Friendly Protocol Docs

Core idea: a polished product documentation platform with crypto protocol
subtlety: precise, navigable, calm, and slightly playful through illustration
and pastel accents.

Palette:

- off-white documentation canvas;
- pastel blue for navigation and links;
- light green for verified/reproducible states;
- soft amber for benchmark caveats;
- muted red for live-money warnings.

Typography:

- product docs sans with high legibility;
- neutral monospace for code, config, and commands;
- clear hierarchy optimized for scanning.

Hero illustration:

- small cartoon control console showing Docs, Research, Backtester, and
  Architecture as product modules.

Layout:

- conventional docs shell: top nav, search, sidebar, content, right toc;
- home page is mostly navigation and orientation, not marketing;
- diagrams are clean product components with pastel labels.

Best for:

- production readiness;
- discoverability;
- keeping public docs professional while allowing lo-fi accents.

Risk:

- may feel less distinctive than other boards unless the hero art and diagrams
  carry enough `crypt` personality.

## Board 5: Cartoon Execution Room

Core idea: the live runtime is the signature visual: a soft cartoon operations
room where backtests, exchange sync, Telegram notifications, and docs all feed
into a controlled execution flow.

Palette:

- pale peach and cream base;
- soft blue for exchange/runtime;
- mint for backtester parity;
- coral for operator warnings;
- dark warm gray for text.

Typography:

- friendly documentation sans;
- compact status labels;
- monospace chips for runtime env keys, strategy files, and symbols.

Hero illustration:

- lo-fi control room with panels for OKX sync, strategy config, backtester
  replay, and Telegram reporting;
- public-safe and conceptual, with no real balances or secrets.

Layout:

- home page starts with runtime-oriented intro, then docs entry grid;
- live execution page gets the richest visual treatment;
- safety callouts are prominent and repeated where necessary.

Best for:

- making live execution visible as an active product capability;
- crypto-native readers who want to understand the operational path;
- strong visual identity.

Risk:

- can over-emphasize live trading versus the broader research workbench unless
  Research and Backtester pages are equally strong.

- `Board 3`;
- `Board 4`;
- `Board 5`;

- corrections such as lighter, darker, less mascot, more technical, or more
