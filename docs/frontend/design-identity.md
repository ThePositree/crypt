# Design Identity

Status: initial static site established.
Revision: 1
Approval source: scoped implementation from owner request.

This identity covers only the initial static site in `site/`. Broader dynamic
app work still needs explicit owner direction and proportional onboarding.

## Core Feeling

- Decision: focused research operations, not consumer fintech excitement.
- Evidence: `README.md` frames `crypt` as a research workbench plus live OKX
  execution module.

## Personality

- Decision: precise, calm, technical, and evidence-oriented.
- Evidence: repository docs emphasize runtime truth, exact backtests, benchmark
  reporting, and live/backtest reconciliation.

## Desired Perception

- Decision: serious internal tool with enough polish to be readable by a
  technical reviewer.
- Evidence: first website scope is owner/agent orientation, not a public SaaS
  funnel.

## Visual Tension

- Decision: light analytical surface contrasted with one dark execution band.
- Evidence: live money needs a visually distinct trust-boundary section.

## Signature Traits

- Trait: read-only status labels.
- Product purpose: prevent the static site from implying exchange control.

- Trait: dense evidence cards.
- Product purpose: route users to canonical repository sources quickly.

- Trait: illustrative chart panel.
- Product purpose: make the strategy-workbench subject visible without using
  fake live account data.

## Anti-Identity

- Avoid: guaranteed-return language.
- Reason: unsupported and unsafe for strategy research.

- Avoid: generic AI trading startup visuals.
- Reason: the project is an internal research/execution workbench.

- Avoid: controls that resemble order placement.
- Reason: live-money actions are out of scope for the static site.

## Implementation-Dependent Exploration Record

- Execution context and methods used: single static implementation with local
  CSS tokens and canvas chart.
- Date: 2026-08-31.
- Approved Visual Direction revision: scoped implementation without separate
  direction boards.
- Known limitations: public audience, brand depth, and dynamic app direction
  remain unresolved.
