## Core Feeling

- Decision: playful lo-fi documentation for a serious crypto framework:
  approachable, calm, technical, hand-curated, and map-like.
- Evidence: owner requested playful cartoon lo-fi in pastel tones and
  framework-style documentation for developer-crypto traders; owner selected
  Board 3, `System Islands Atlas`, on 2026-09-02.

## Personality

- Decision: atlas guide for a technical framework: it helps readers cross from
  concept to subsystem without becoming a trading dashboard.
- Evidence: owner excluded runtime results and requested curated docs in source.

## Desired Perception

- Decision: "this is a large system whose islands, bridges, and risk borders I
  can understand and navigate quickly."
- Evidence: owner requested both tutorial and reference models, full-content
  search, diagrams, statuses, and next-reading blocks; Board 3 makes the dual
  route/reference model visually explicit.

## Visual Tension

- Decision: playful atlas maps and abstract guide markers balanced against
  dense framework-docs structure, risk labels, and precise technical copy.
- Evidence: owner requested playful abstract mascots and risk marking for live
  money, OKX execution, config, and no-look-ahead bias; Board 3 was approved
  as primary.

## Signature Traits

- Trait: abstract lo-fi doc helpers.
- Product purpose: make a large technical portal memorable without implying
  trading advice or live monitoring.

- Trait: pastel system maps and hand-drawn diagram accents.
- Product purpose: explain data/decision flows in a readable, non-dashboard
  way.

- Trait: subsystem islands connected by bridges.
- Product purpose: make the architecture/reference model memorable while
  preserving explicit boundaries between research, backtesting, live execution,
  data, configuration, operations, and glossary content.

- Trait: maturity and risk badges.
- Product purpose: keep operational boundaries visible while preserving
  scannability.

## Anti-Identity

- Avoid: profit-centric visuals, candlestick-dashboard hero layouts, live PnL
  cards, exchange balance panels, and dark finance terminal aesthetics.
- Reason: the portal documents how the code works; it must not look like a
  runtime trading dashboard or imply performance results.

- Avoid: one-note purple/blue gradient UI.
- Reason: global frontend instructions reject dominant purple-blue gradients
  and one-hue palettes.
