# Design Identity

Status: preliminary, pending Visual Direction Boards.
Revision: 1
Approval source: owner onboarding answers from 2026-09-03; final approval
pending Visual Direction Approval.

This repository does not currently contain an active frontend product surface.
This preliminary identity records owner input for the first `crypt docs`
portal and guides visual exploration.

## Core Feeling

- Decision: playful lo-fi framework documentation that still treats trading
  risk seriously.
- Evidence: owner requested playful lo-fi style, abstract mascots, Russian
  docs for a developer-crypto trader, and explicit risk marking.

## Personality

- Decision: curious, technical, approachable, and precise.
- Evidence: owner wants documentation like a framework, not a dashboard or
  marketing page; code should be explained without source quotations.

## Desired Perception

- Decision: a serious crypto engineering workbench made understandable through
  friendly illustrated documentation.
- Evidence: owner requested huge documentation portal, all major framework
  sections, search, diagrams, snippets, maturity labels, and mascots.

## Visual Tension

- Decision: playful abstract mascots and soft lo-fi surfaces must coexist with
  dense technical navigation, risk badges, source maps, and framework-doc
  structure.
- Evidence: owner requested playful style and mascot presence while also
  requiring complete deep technical documentation.

## Signature Traits

- Trait: abstract helper mascots used as orientation markers, not comic relief.
  Product purpose: make dense technical docs more memorable without weakening
  live-money warnings.
- Trait: hand-drawn or notebook-like diagrams for data and decision flows.
  Product purpose: explain causal flow from candles to decisions and execution.
- Trait: theme-aware React SVG diagrams with lo-fi drawing cues.
  Product purpose: keep diagrams readable in light and dark modes while
  preserving the playful documentation identity.
- Trait: maturity and risk badges embedded near headings and navigation.
  Product purpose: show what is stable, research, operational, archived, or
  risky before the user acts on information.

## Anti-Identity

- Avoid: generic SaaS landing-page gloss.
  Reason: the requested product is documentation for developers, not a sales
  funnel.
- Avoid: dark trading-terminal visual dominance.
  Reason: owner asked for playful lo-fi and both light/dark themes, not a
  one-note exchange dashboard.
- Avoid: unsupported profitability or AI-trading hype.
  Reason: benchmark and live production rules are nuanced and must stay honest.
