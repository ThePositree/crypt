# Configuration

- Route: `/docs/configuration`.
- Purpose: explain application and execution configuration safely and completely.
- Primary action: copy a minimal dry-run environment block.
- Hierarchy: configuration precedence; base settings; credentials; data/logging;
  execution switches; strategy/path; risk/geometry; sync/recovery; Railway groups.
- Messaging: from `Which setting controls this?` to `I know default, effect and risk`.
- Content contract: current settings classes and `.env.example`; secrets are never shown.
- Discovery: every public setting key, prefix, default category, and common symptom.
- Interactions: base/execution/deployment tabs, search/filter, copy, group disclosures.
- States: valid, missing required, live credentials absent, conflicting, legacy migration,
  secret redaction, zero filter results.
- Responsive: key/value tables become stacked records without hiding defaults.
- Accessibility: filter results announced; required/risky labels are textual.
- Related: Quick Start, Live Execution, Troubleshooting.
- Acceptance: important setting groups have name, default, effect, safety and source evidence.
