# Strategies

- Route: `/docs/strategies`.
- Purpose: explain configuration, registry, signals, context and extension seams.
- Primary action: inspect a source-backed example strategy config.
- Hierarchy: strategy role; config anatomy; registry/loading; inputs and closed
  candles; decision output; execution context; composition; extension checklist.
- Messaging: from `Where is strategy behavior defined?` to `I can trace or extend it`.
- Content contract: examples are illustrative/current and never framed as profitable.
- Discovery: registry names, config fields, signal/event terminology, extension hooks.
- Interactions: annotated config tabs, disclosures, code copy, related routes.
- States: valid/invalid config, unsupported strategy, missing inputs, multi-signal overflow.
- Responsive: annotations move below code; code remains locally scrollable.
- Accessibility: annotation references use text, not connector color alone.
- Related: Architecture, Backtester, Research, Configuration.
- Acceptance: reader understands pure strategy behavior versus execution geometry.
