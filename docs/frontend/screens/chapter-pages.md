# Chapter Page Family Contract

Applies to Architecture, Research, Strategies, Execution, Concepts, and
History.

## Purpose And Layout

Each page answers one coherent question using a chapter header, local table of
contents, explanatory specimens, diagrams or evidence, related concepts, and
previous/next navigation. Desktop may pin the local index; mobile places it in
a disclosure below the chapter summary.

## Trust Boundaries

Canonical project documentation supplies curated facts. Public evidence must
carry dates, source type, methodology, and limitations. Execution explains
behavior but exposes no commands or controls. History cannot be mistaken for
the current architecture.

## Required States

Normal, loading fallback, empty/not applicable, error/unavailable, partial
evidence, disabled unsafe action explanation, and local overflow for wide data.

## Accessibility And Responsive Behavior

Heading hierarchy, named figures, accessible chart summaries, keyboard local
navigation, glossary definitions on focus/click, visible focus, reduced motion,
and no global horizontal overflow.
