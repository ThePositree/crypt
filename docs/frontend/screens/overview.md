# Overview Screen Contract

## Purpose

Give a first-time public visitor a correct mental model of `crypt` and a clear
next step without implying that the portal can operate the system.

## Information Hierarchy

1. Plain-language promise and explanation-only boundary.
2. Recurring field researcher and crypto cue.
3. One-decision/two-path system map.
4. Guided chapter cards and evidence principles.
5. Safe example preview, glossary entry, and history route.

## States And Responsive Behavior

Search supports normal/loading/empty/error. Optional illustration failure keeps
the text. Mobile becomes one ordered specimen trail; desktop uses an asymmetric
hero and two-column evidence spreads. Charts/tables scroll locally.

## Accessibility Requirements

One H1, semantic landmarks, skip link, visible focus, named diagrams, text
summary for visual evidence, keyboard search/menu/theme, reduced motion.

## Acceptance Criteria

The visitor can state what the project is, distinguish research/backtest from
owner-selected live execution, understand that the page has no controls, and
continue to Architecture or Search.
