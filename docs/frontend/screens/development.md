# Development And Testing

- Route: `/docs/development`.
- Purpose: help contributors navigate modules and run supported validation.
- Primary action: copy the appropriate lint, type or test command.
- Hierarchy: repository map; environment; module ownership; change workflow;
  tests; lint/format/type checks; common extension paths; documentation freshness.
- Messaging: from `Where do I change this?` to `I can make and validate a scoped change`.
- Content contract: public-safe contributor knowledge; internal owner-only process excluded.
- Discovery: source modules, test groups, ruff, mypy, pytest, uv commands.
- Interactions: command copy, module-map nodes, validation tabs, related routes.
- States: passing, failed validation, missing optional data/tool, long-running check warning.
- Responsive: module tree scrolls locally; workflow becomes ordered stages.
- Accessibility: tree is also represented as semantic nested lists.
- Related: Architecture, Strategies, Backtester, Troubleshooting.
- Acceptance: reader can locate code ownership and run the supported checks.
