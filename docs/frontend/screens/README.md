# Screen Contracts

Store persistent screen contracts here. Before materially changing a meaningful
screen, update the relevant contract when necessary, then implement.

Use this structure when applicable:

```md
# Screen Name

## Purpose

## User Goals

## Primary Action

## Information Hierarchy

## Layout

## Sections

## Components

## States

- loading
- normal
- empty
- error
- disabled
- overflow
- partial data

## Responsive Behavior

## Visual Emphasis

## Related Screens
```
