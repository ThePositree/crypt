# Quick Start

- Route: `/docs/quick-start`.
- Purpose: guide the complete install-to-dry-run path without sending orders.
- Primary action: execute/copy the next safe command; endpoint links to Architecture.
- Hierarchy: prerequisites; install; environment; data check/backfill; bounded
  backtest; artifact types; execution-only dry-run; what changed; next reading.
- Messaging: from `I want crypt running` to `I completed and understood a safe
  dry-run`; answer missing-data and accidental-order objections beside commands.
- Content contract: commands come from current CLI/runtime; no sandbox-only env
  vars in owner-facing code; no project performance values.
- Discovery: index every command, flag, env key, artifact type, and error phrase.
- Interaction inventory: step anchors, copy buttons, OS/config tabs,
  explanations, related links, search, previous/next.
- States: copy success/failure; missing data recovery; blocked unsafe config;
  dry-run success; code overflow.
- Responsive: steps remain ordered; diagrams become vertical; code scrolls locally.
- Accessibility: ordered list semantics, warnings outside color-only treatment,
  tabs/disclosures keyboard operable.
- Related: primary journey, Data, Backtester, Configuration, Live Execution.
- Acceptance: a literal reader can reach `--execution-only --once` in dry-run
  with explicit fake capital and understand that no order was placed.
